# Memória, identidade e plugins da versão 2.0

## Memória em camadas

A memória deverá ser separada por função. A conversa atual será a memória de trabalho; decisões e resultados importantes formarão memória episódica; documentos e notas serão conhecimento recuperável; e procedimentos aprovados formarão memória procedural.

| Camada | Persistência | Exemplo | Controle do proprietário |
|---|---|---|---|
| Trabalho | Sessão | Mensagens, plano e arquivos selecionados | Apagar, exportar ou resumir |
| Episódica | Projeto/usuário | “O projeto usa Vulkan e testes locais” | Aprovar antes de registrar |
| Semântica | Índice local | Trechos do Obsidian e PDFs | Escolher diretórios e reindexar |
| Procedural | Biblioteca de skills | “Como iniciar um app local” | Revisar versão e permissões |
| Identidade | Arquivo protegido | Nome, estilo, princípios e limites | Alteração manual do proprietário |

O sistema não deverá gravar cada conversa automaticamente como verdade permanente. A IA deverá propor uma memória, explicar a origem e pedir autorização quando o registro puder influenciar futuras decisões. Cada memória deverá possuir origem, data, projeto, confiança, validade e opção de remoção.

## Integração com Obsidian

O vault poderá ser uma fonte de conhecimento, mas não deverá ser tratado como instrução soberana. O conteúdo recuperado será marcado como referência e separado das políticas do sistema. Textos encontrados em notas não poderão conceder permissões ao agente, liberar terminal ou modificar a política.

A indexação deverá ser incremental, observar alterações e permitir exclusões. O usuário poderá escolher pastas, tags e tipos de arquivo. A resposta deverá mostrar quais notas foram usadas para que a memória não se torne uma caixa-preta.

## Identidade configurável

A identidade deverá viver em arquivos versionados, por exemplo:

```text
mind/
├── identity.md       # nome, tom, idioma e comportamento
├── principles.md     # princípios aprovados pelo proprietário
├── boundaries.md     # limites que não podem ser ignorados
├── preferences.md    # preferências do usuário
└── skills/           # procedimentos locais revisados
```

A IA poderá ler esses arquivos, mas não deverá editá-los sozinha. Uma proposta de alteração deverá ser exibida como diff e exigir aprovação manual. A identidade também não deverá substituir a política de segurança ou a confirmação do proprietário.

## Plugins

Plugins serão pacotes locais com manifesto, versão, escopos, dependências e pontos de entrada. O manifesto deverá declarar se o plugin lê arquivos, escreve arquivos, executa processos, usa rede, acessa o Obsidian ou chama modelos.

```toml
id = "local.preview"
version = "0.1.0"
entrypoint = "plugin.py"

[permissions]
read_workspace = true
write_workspace = false
execute_process = true
network = false
external_publish = false

[approval]
first_install = true
side_effects = true
```

Plugins não deverão receber acesso ao objeto interno do agente nem às credenciais. O gateway fornecerá apenas APIs explicitamente autorizadas. Um plugin poderá ser pausado, revogado, atualizado ou removido sem apagar as conversas e memórias do usuário.

## Marketplace e origem

A primeira versão não deverá instalar plugins automaticamente de um marketplace aberto. A instalação deverá aceitar um diretório local, arquivo assinado ou pacote cuja origem seja revisada pelo proprietário. Cada plugin deverá exibir hash, versão, permissões, arquivos incluídos e data de instalação.

## Personalização sem descontrole

A personalização deverá alterar comportamento, não remover salvaguardas invisivelmente. O usuário poderá escolher modelo, prompt de identidade, idioma, formato de plano, ferramentas, interface, memória, notificações e nível de autonomia. A política de permissões deverá permanecer separada e visível.

## Critério de memória confiável

Uma memória somente poderá influenciar uma ação quando o sistema puder mostrar sua origem, relevância, data e escopo. Memórias conflitantes deverão ser apresentadas ao usuário ou tratadas como hipóteses, nunca fundidas silenciosamente. O proprietário deverá conseguir consultar “por que você sabe isso?” e remover a informação correspondente.
